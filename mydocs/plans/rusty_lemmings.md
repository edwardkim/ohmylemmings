# 🐹 Rusty Lemmings 프로젝트 기획 및 설계서

## 1. 프로젝트 개요 (Overview)

### 1.1. 프로젝트 목적
본 프로젝트는 1991년 출시된 고전 명작 게임 '레밍즈(Lemmings)'의 오리지널 로직을 최신 시스템 프로그래밍 언어인 **Rust**로 완벽하게 포팅하는 것을 목표로 합니다. 오리지널 게임의 데이터 파일(DAT)을 그대로 활용하면서도, 현대적인 메모리 안전성과 WebAssembly(WASM)를 통한 크로스 플랫폼 구동 환경을 구축합니다.

### 1.2. 프로젝트 의의
- **오픈소스 생태계 기여:** 현재 GitHub에 부재한 'Rust 기반 완벽한 레밍즈 포팅 엔진'이라는 블루오션을 개척합니다.
- **최신 기술 스택 검증:** 픽셀 단위 지형 파괴와 수백 마리의 객체 상태를 관리하는 로직을 Rust의 안전한 동시성 모델과 SIMD로 최적화합니다.
- **AI 협업 워크플로우 적용:** 문서 기반의 하이퍼 워터폴(Hyper-Waterfall) 아키텍처를 도입하여 AI 코딩 어시스턴트(Qwen, Claude 등)의 컨텍스트 유지 능력을 극대화하는 레퍼런스 프로젝트로 삼습니다.

---

## 2. 시스템 아키텍처 및 기술 스택

### 2.1. 코어 엔진 분리 (Core Logic)
- **언어:** Rust (가능한 부분은 `no_std` 지향)
- **특징:** 그래픽 렌더링이나 I/O와 완전히 분리된 순수 상태 머신.
- **역할:** 레밍의 상태(걷기, 파기, 막기 등) 업데이트, 충돌 처리, 픽셀 맵 변형 로직 처리.

### 2.2. 플랫폼 바인딩 (I/O & Rendering)
- **데스크톱 (Native):** Rust + SDL2 (저지연 그래픽, 오디오 출력 및 키보드/마우스 입력)
- **웹 (Web):** Rust + WebAssembly (WASM) + HTML5 Canvas / WebGL

### 2.3. 레퍼런스 모델 (리버스 엔지니어링 기반)
오리지널 소스코드가 없으므로, 이미 검증된 다음의 오픈소스 로직을 Rust로 번역(포팅)하는 방식을 취합니다.
- **Lemmix (Delphi):** 오리지널 게임의 틱(Tick) 및 물리 엔진 로직 복제 레퍼런스.
- **Lemmings.ts (TypeScript):** 리소스(DAT 파일) 파싱 및 웹 브라우저 구동 구조 레퍼런스.

## 3. 핵심 구현 과제 및 설계 방안

### 3.1. 오리지널 리소스 파싱 (DAT & VGASPEC 파일)
- **목표:** 오리지널 DOS 버전의 레벨 데이터, 지형 타일, 스프라이트 맵을 바이트 단위로 읽어 구조체로 역직렬화(Deserialization)합니다.
- **설계:** `nom` 또는 `binrw` 크레이트를 활용하여 바이너리 데이터를 안전하게 파싱합니다. 파싱된 데이터는 불변 상태로 메모리에 적재하여 렌더러와 로직 엔진에 제공합니다.

### 3.2. 실시간 픽셀 지형 파괴 (Terrain Destruction)
- **목표:** 폭발(Bomber), 파기(Digger) 등의 행동으로 지형 마스크가 실시간으로 변형되는 오리지널의 특징을 구현합니다.
- **설계:**
  - 1D 배열 기반의 가상 비트맵(VRAM)을 구성합니다.
  - Rust의 `std::simd` 또는 비트 연산 최적화를 통해 픽셀 충돌 검사와 지형 삭제 연산을 고속으로 처리합니다.

### 3.3. 결정론적 틱(Tick) 기반 게임 루프
- **목표:** 디스플레이 주사율(60Hz, 144Hz)에 상관없이 게임 속도와 물리 엔진이 동일하게 작동해야 합니다.
- **설계:** 렌더링 프레임(FPS)과 논리 업데이트 틱(Tick)을 분리(Decoupling)합니다. 고정 시간 간격(Fixed Time Step) 패턴을 적용하여 오리지널 DOS의 사이클을 모사합니다.

## 4. AI 기반 개발 워크플로우 (Hyper-Waterfall)

AI의 기억 상실(Context Window 초과)을 방지하고 일관된 아키텍처를 유지하기 위해, 프로젝트 루트의 `mydocs/` 폴더에서 다음 구조로 문서를 관리합니다.

*   📂 `mydocs/`
    *   📁 `plans/`: 마일스톤 및 전체 아키텍처 문서 (본 문서 포함)
    *   📁 `orders/`: AI에게 내릴 프롬프트 지시어 템플릿 및 모듈별 요구사항
    *   📁 `feedbacks/`: 사용자 및 리뷰어의 피드백과 반영 결과
    *   📁 `tech_insights/`: Lemmix나 Lemmings.ts에서 추출한 상태 머신 상수값, 데이터 패킷 구조 등 도메인 지식
    *   📁 `troubleshootings/`: Rust의 라이프타임 에러, WASM 빌드 에러 등 해결 이력 기록

**작업 방식:** AI에게 코딩을 지시하기 전, 항상 `mydocs/`의 관련 문서를 먼저 읽게 하여 컨텍스트를 동기화한 후 TDD(테스트 주도 개발) 방식으로 작은 모듈부터 구현합니다.
