# #202 사용자 로컬 MP3 BGM 구현

이슈: https://github.com/edwardkim/ohmylemmings/issues/202

상태: 구현·검증·배포와 2026-10-24 메인테이너 최종 확인까지 완료했다. [최종 인수](../reports/issue-202_local_mp3.md#메인테이너-최종-인수-완료-2026-10-24). 아래 OPEN 문구는 확인 전 기록이다.

메인테이너가 [#200 검토](../reports/issue-200_custom_bgm_review.md)의 로컬 파일 방식을 채택하고 구현을 지시했다. Web과 Native에서 사용자 MP3를 업로드/번들링 없이 재생하고 원본 효과음을 유지한다.

1. TDD로 공통 OPL 출력의 음악/효과음 gain을 분리한다. 기본100/100은 기존 PCM과 동일하며, 원본 드라이버/사건/채널 배정/게임 규칙은 보존한다. 무음 음악도 시계/채널은 진행시켜 효과음 동작이 바뀌지 않게 한다.
2. Web은 File/object URL·HTMLAudioElement와 기존 AudioContext를 사용한다. 원본/내 음악/끄기·개별 음량·반복·상태/오류/재시도, 비동기 교체/취소·새 세대·숨김/결과를 처리한다.
3. Native는 사용자 MP3 드롭/명시적 파일 경로, bounded 작업자 디코딩/리샘플링·스테레오 믹싱을 구현한다. 원본 mono 프로브 호환을 유지하고 새 경로를 별도로 인수한다. 신규 의존성은 버전/codec/라이선스/공급원을 고정한다.
4. 합성 MP3 fixture로 손상/중단/교체/긴 음악/loop·mix·실제 브라우저/SDL을 검증한다. 기존 전체 오디오/C/WASM 및 플랫폼 패키지 회귀·CI·self-review 후 문서/개발 미리보기를 동기화한다. 실제 사람 청취는 별도로 기록한다.

기본은 원본 BGM, 내 음악은 한 곡 반복이다. 게임 Pause에서는 음악을 계속하고 결과/숨김에서 정지, 재시작/다음 레벨/복귀에서 처음부터 재생한다. 음악 오류는 게임/효과음을 중단하지 않는다. 준비·재생·실패·수동 재생 필요 상태를 표시한다. 공개 v0.2.0 태그/asset/버전 노트는 변경하지 않는다. #113 성능 목표와 #165 기존 인수는 보존한다.

## 구현·자동 인수 완료

1~4의 제품 구현·회귀·실제 Web/Native 실행·플랫폼 CI7개·self-review·PR #203 병합을 완료했다. [최종 검증](../reports/issue-202_local_mp3.md#최종-ci병합메인테이너-제공-파일-검증)을 따른다. 메인테이너가 제공한 MP3 두 곡의 디지털 재생/교체/반복/효과음 동시 출력을 확인했으며, 새 MP3 실제 청취 확인을 마지막 인수로 남겨 #202 OPEN을 유지한다.
