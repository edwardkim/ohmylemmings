# #196 웹 점진적 자산 다운로드

이슈: https://github.com/edwardkim/ohmylemmings/issues/196


상태: **2026-10-24 완료**. [정식 게시·공개 인수](../reports/issue-194_release_v020_completion.md)를 따른다. 아래 내용은 구현/게시 준비 당시 기록이다.

메인테이너가 #194 릴리즈 준비 중 웹 초기 다운로드 축소와 플레이 중 백그라운드 준비를 지시했다. v0.2.0 태그/공개 게시는 보류한다. 배포 ZIP 크기와 실제 첫 접속 전송량을 구분하고, 현 테마별 HD 로더·자산 구성·캐시/취소 동작을 조사한다. 첫 레벨 필수 자산을 우선 처리하고 향후 자산은 제한된 백그라운드 큐로 준비하는 방식을 비교한다. 렌더 픽셀·게임 상태·원본 선택과 데스크톱 오프라인 패키지를 보존한다.

먼저 실제 카탈로그 페이지별/스코프별 전송량, 압축 가능성, 초기 레벨 의존성을 측정한다. 공식 Fetch Priority·Compression Streams·Cache API 자료를 검토하고 첫 플레이 바이트 예산·재방문·중단·오류·버전 혼용 방지 검증을 설계한다. 결과와 선택 근거를 기록한 후 구현/TDD 및 실제 제한 네트워크 검증을 진행한다.

## 필수 다운로드 UX

메인테이너 추가 지시: 게임 진행에 필요한 다운로드는 실제 수신 바이트/필수 총 바이트·진행률을 표시한다. 첫 플레이 준비와 레벨 전환 대기를 구분하며 플레이 중 다음 레벨 백그라운드 준비도 별도 상태로 알린다. 필요한 자산이 없는 동안에는 시뮬레이션 시계를 정지하고, 실패·오프라인·캐시 손상은 사용자 메시지/재시도로 복구한다. 가짜 시간 기반 진행률을 사용하지 않는다. 키보드/스크린리더용 progress/상태 의미를 제공한다.

## 선택과 검증 상태

[결과 보고서](../reports/issue-196_web_progressive.md)의 레벨 키 계획+무손실 gzip·지형 분할/즉시 다음 레벨 준비·버전 캐시·진행률/오류 UX를 구현했다. 첫 HD 예산24MiB 이내와 필수 외 선다운로드 없음, 캐시/오류/전체화면·시계 정지를 로컬에서 확인했다. 실제 초기 HD는19,751,567바이트다. 최종 릴리즈 소스 전체 CI와 공개 Pages 인수를 계속한다.
