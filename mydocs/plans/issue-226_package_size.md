# 배포 용량 최적화

담당 [#226](https://github.com/edwardkim/ohmylemmings/issues/226), 조사 [#224](../reports/issue-224_web_size.md).

1. 실제 런타임 제작 매니페스트의 atlas/provenance/extension 의존성을 따라 소스 자산을 선별하고 과거 디자인·프리뷰·보고 이미지를 배포 소스에서 제외한다. 저장소 이력 자체는 삭제하지 않는다.
2. CI의 자체 완결 패키지는 실행 검증에 사용하고, 정식 게시에서 같은 런타임 바이트를 보존하며 공통 대응 소스를 별도 다운로드로 분리한다. Native4종 중 macOS 앱 서명 범위는 건드리지 않는다.
3. 실행 패키지에 버전/크기/해시로 고정된 소스 URL·재빌드 안내를 넣고 공개 전 소스 누락/불일치 검증을 강제한다. Pages에도 동일한 소스 링크를 제공하며 큰 소스 아카이브를 다시 호스팅하지 않는다.
4. 미사용/중복 파일 허용 목록과 생성 캐시 잔여를 조사하고 안전하게 제거한다. 실제 쓰는 원본 모드·레벨/캐릭터·라이선스·폰트는 임의 삭제하지 않는다.
5. 손상/누락 회귀 테스트, 실제 source 추출 빌드·HD 재생성 바이트 대조, 패키지 실행과 전후 크기 검증 후 보고한다. 기존 공개 태그/릴리즈 파일은 유지한다. 새 버전 게시 자체는 별도다.
