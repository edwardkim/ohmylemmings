# G08-05 VGA 기술 패널·미니맵 계약

이슈: [#56](https://github.com/edwardkim/ohmylemmings/issues/56), 상위 [#1](https://github.com/edwardkim/ohmylemmings/issues/1).

## 리소스와 기준의 차이

[#17](issue-17_main_ui.md)의 구간 6 패널/폰트는 고정 Lemmix `40e9bc34451f0e9127fd53b290a3877e700d143d`의 `Game.SkillPanel.ReadBitmapFromStyle`과 같습니다. 실제 고정 DOS VGA 영상에는 다른 패널과 글꼴이 보입니다. MAIN.DAT 구간 2의 `[0,6400)`은 320×40·4플레인 VGA 패널, `[6400,6560)`은 기존 숫자, `[6560,8384)`는 8×16·3플레인 글리프38개입니다. 구간 6의 기존 API와 출력은 유지하고 `VgaSkillPanel`/`VgaPanelGlyphs`를 추가했습니다. `inspect_ui`는 이제21묶음239이미지를 출력합니다. 기존200이미지의 픽셀과 메타데이터는 보존합니다.

원본 `VGALEMMI.EXE` 파일 오프셋 `c1a0..c1b7`은 UI 상위8색의6비트 DAC 값입니다: `(0,42,0),(21,63,21),(21,21,21),(42,0,0),(42,21,0),(0,42,42),(63,21,63),(42,0,42)`. 하위8색은 기존 게임 고정색이며 색7은 레벨 지형 첫 색입니다. UI 상위8색에 지형 팔레트를 적용하면 잘못된 색이 됩니다. 글꼴의 세 번째 저장 플레인은 VGA 비트3에 연결하므로 색상 인덱스는 `(c&3)|((c&4)<<1)`입니다. 숫자의1비트는 고정 흰색3에 연결합니다. 라이브러리는 인덱스를 그대로 반환하고 팔레트 합성은 SDL 어댑터가 담당합니다.

구간2 이미지·글꼴과 색 연결은 기존 #44의 독립 DOS 영상 두 개를 재사용해 비교합니다. 새 DOS 실행으로 집계하지 않습니다. 원본 파일 해시와 기존 녹화 설정/매퍼·파일을 확인하며 원본 파생물은 ignored `assets/local/`에만 보관합니다.

## 좌표와 입력

게임은320×160, 패널은 y160..199입니다. 고정 `Game.SkillPanel.SetButtonRects`의 반열린 영역 `(16n+1,176)..(16n+15,198)`을 클릭 영역으로 씁니다. 버튼 순서는 감소/증가, Climber/Floater/Bomber/Blocker/Builder/Basher/Miner/Digger, Pause/Nuke입니다. 틈과 패널 상단은 직업 할당으로 내려가지 않습니다. 선택 테두리는 DOS 관측에 맞춰 `(16n,176)`에서16×24입니다.

키보드 F/C/E/K/U/M/B/D와 기술 버튼은 같은 선택 필드를 사용합니다. 기존 네이티브의 초기 Digger 선택을 유지합니다. 선택은 표현 상태이고 실제 할당은 기존 안정된 개체 ID 명령으로 기록합니다. 포인터 선택 우선순위·RightClickGlitch는 이 이슈의 범위 밖입니다. 커서 정보 문구도 현재 선택기의 단순 근접 규칙을 사용하며 전체 DOS 커서 동작 인증은 아닙니다.

생성 속도 클릭은 즉시1회, 계속 누르면 control_step마다1회 증감합니다. 폴링·렌더 횟수와 분리하며 초기값..99로 제한합니다. 마우스를 놓거나 창이 포커스를 잃으면 중단합니다. Pause 중 속도 조정·기술 선택/할당은 기존 네이티브 계약을 유지합니다. Pause 버튼은 기존 Pause/Resume 명령이고 Nuke 버튼은 참조처럼 더블클릭만 허용합니다. 기존 N 단축키는1회 입력입니다. Pause 중 Nuke는 받지 않습니다.

재생 중 실제 패널의 시뮬레이션 명령은 차단합니다. 카메라/미니맵은 표현 조작으로 허용합니다. 결과 확정 뒤 패널 입력은 무시하고 기존 결과 장면 명령만 처리합니다. 재시작·다음 레벨은 새로운 View/Controls를 만들어 누름/드래그·포인터·선택·카메라를 초기화합니다. SDL 논리 좌표를 사용하며1000×700 창의3배 배율/20·50 여백에서 실제 마우스 입력을 검사합니다.

## 표시와 미니맵

숫자는17px 패널 Y에8px 높이로 그립니다. 두 자리0패딩·99상한,0은 빈 흰색 영역입니다. OUT은 아직 제거되지 않은 개체와 폭발 파티클 진행 중인 개체, IN은 Nuke 반영 현재 최대 인원 기준 정수 구출률, TIME은 기존 시계의 분-초입니다. 생성 속도의 왼쪽은 초기값, 오른쪽은 현재값입니다. Pause는 추가 테두리로 구분합니다.

DOS EXE `7b59..7b75`는16개 지형 비트 중9개 이상인 그룹을 미니맵의 지형 픽셀로 만듭니다. `7a6c`는 첫 행을 비웁니다. 패딩을 제거한 네이티브 좌표에서는 미니맵 `(mx,my)`가 `x=(mx-1)*16`, `y=(my+1)*8`의 수평16픽셀을 집계합니다. `mx=0`/`my=0`은 비고 범위 밖은 잘립니다. 살아 있는 개체와 파티클 진행 중인 개체는 `(x/16+1,y/8-1)`에 고정 녹색2로 표시합니다. 카메라 테두리는 DOS `7b7a..7cd7`과 영상의24×20이며 Lemmix의25×20과 구별합니다.

지도는 `(208,178)`의104×20입니다. 클릭/왼쪽 드래그는 반열린 `(208,178)..(311,197)` 안에서 `camera=(x-208)*16-176`을 월드 범위로 제한합니다. 지형/벽돌의 현재 점유를 매번 읽으므로 변경이 즉시 반영됩니다. 원본의 열별 분산 갱신 지연은 재현하지 않습니다. 게임 시뮬레이션과 카메라/지도 사이에는 역방향 의존성이 없습니다. 코어는 폭발 파티클 시작 때 이미 제거로 정규화하므로, OUT/미니맵 표시에서는 파티클 타이머가0이 될 때까지 원본 DOS의 표시를 유지합니다.

## 검증 재현과 한계

```sh
make check
python3 tools/check_panel.py --evidence assets/local/panel-check
# 별도의 Xvfb DISPLAY에서:
python3 tools/verify_panel.py --xdotool /usr/bin/xdotool --evidence assets/local/panel-x11
python3 tools/verify_panel.py --xdotool /usr/bin/xdotool --assets assets/local/dos-original --evidence assets/local/panel-original-x11
```

`compare_panel_dos.py`는 동일한 전체 게임 영역 앵커에서 HUD11648픽셀의 명시된 영역을 RGB565로 대조합니다. Climber/Digger의 서로 다른 선택 테두리와 DOS 커서가 있는 Miner 슬롯, 합계1152픽셀은 비교 영역 밖입니다. 전체 HUD 차이 수도 따로 기록하며 전체320×200 일치로 표현하지 않습니다. 비동기 HUD 갱신과 게임 앵커를 같은 내부 틱으로 간주하지 않습니다. 원본 결과 아트·음향·웹·전체 DOS 상태/입력 틱 인증과 G08 전체 완료는 후속입니다.
