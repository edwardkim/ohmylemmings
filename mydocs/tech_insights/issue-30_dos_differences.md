# DOS 화면·속도 차이 추적

이슈: [#30](https://github.com/edwardkim/ohmylemmings/issues/30), 관측 [#28](https://github.com/edwardkim/ohmylemmings/issues/28).

## 확인한 범위

Fun01에서 640×400 RGB565 영상을 실제 실행에서 확보했습니다. 네이티브 0/35/54/60/100/170/340 상부 320×100 장면이 나타나지만 전체 320×160 장면은 초기 장면 외에는 일치하지 않습니다. 영상 인덱스와 네이티브 control_step은 다른 단위입니다.

## 후속 검증

같은 상부 장면에 해당하는 영상의 전체 차이 픽셀·객체 프레임을 기록합니다. 고정 10000 cycles·PC 2 조건의 영상 간격과 네이티브 17Hz 사이의 차이는 CPU/PC 기종·VGA 수직 주사·DOS 내부 호출을 분리해 분석합니다. 현재 코어 규칙은 수정하지 않았습니다. 전체 호환성 통과로 계산하지 않습니다.

## 세 실행의 확정 증거

[증거 manifest](../../assets/manifests/dos_observation.json)의 세 실행은 같은 일곱 상부 장면이 영상 174~223 / 224~228 / 319~323 / 349~353 / 549~553 / 899~903 / 1749~1753에 나타납니다. 초기 정지 장면은 여러 틱이 같은 그림이라 절대 틱을 알 수 없습니다. 전체 초기 그림의 일치는 219~223입니다.

| 네이티브 장면 | 첫 대응 상부 프레임에서 전체 차이 픽셀 | 차이 경계, 오른쪽/아래 제외 |
|---|---|---|
| 35 | 19 | (234,108)~(264,113) |
| 54 / 60 | 21 | (234,108)~(265,113) |
| 100 / 340 | 26 | (234,108)~(266,113) |
| 170 | 21 | (234,108)~(266,113) |

상부 320×100은 정확히 같고 차이는 출구 장식 주변입니다. 원본을 우선해 객체 애니메이션의 초기 위상/증가 순서를 조사할 근거이며 원인을 이미 확정한 것은 아닙니다.

35~340 장면 사이에서 네이티브 한 호출당 영상 5프레임입니다. `2190197/31250 / 5` ≈ 14.017 장면/초는 현재 설정의 관측값입니다. 채택한 정확한 17Hz를 바로 고치거나 CPU 전체에 일반화하지 않습니다. 여러 CPU 설정·PC 기종의 별도 실험과 내부 틱 계측으로 원인을 분리한 뒤 보정합니다. 이 이슈는 OPEN이며 G06-03의 다음 작업입니다.
