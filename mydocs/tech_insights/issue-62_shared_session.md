# G09-01 공유 세션과 웹 이식 경계

이슈: [#62](https://github.com/edwardkim/ohmylemmings/issues/62) · [진행](../working/issue-62_shared_session.md) · [결과](../reports/issue-62_shared_session.md)

## 책임과 의존 방향

`lemmings-session → lemmings-core`를 추가했습니다. 공유 크레이트는 기존 desktop Session/Pacing을 소유하며 외부 패키지·resources·SDL·브라우저 의존성이 없습니다. `core`와 `resources`의 무할당 no_std 및 `resources → core` 방향은 유지합니다. desktop의 기존 session/pacing 모듈은 공유 구현의 재노출만 담당합니다.

| 경계 | 책임 |
|---|---|
| core | 고정 틱·입력 순서·행동/기술·지형·객체·판정의 무할당 규칙 |
| resources | 호스트가 제공한 바이트의 검증·해석·합성 |
| session | 소유한 개체/지형/수량·입력 목록·틱 조립·완료 결과·재생 시계 |
| desktop | 파일 읽기·자산/레벨 조립·SDL 입력/렌더·시스템 시계·캡처 |
| 향후 web | 파일 선택/바이트 공급·JS/WASM 경계·브라우저 시간·Canvas/입력·수명 관리 |

session은 `std`의 Vec/String/Box와 Duration을 사용합니다. core를 힙 소유 모델로 바꾸거나 session을 no_std로 표시하지 않습니다. 시스템 시각 읽기·파일/네트워크·스레드·렌더 호출은 넣지 않습니다. [Rust 타깃 문서](https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html)는 이 타깃의 std에서 운영체제 기능이 제한됨을 명시합니다. 이번 검증은 고정 Rust 1.93.1에서 실제 공유 라이브러리를 컴파일한 결과입니다.

`render_terrain`/`render_bricks`는 기존 폭발 직후 표현 순서를 위한 마스크 뷰입니다. Session에 그래픽 리소스나 그리기 API를 추가하지 않았으며 기존 마스크 보존 동작을 그대로 옮겼습니다. 포인터의 최종 skill/안정 ID 명령 변환도 공유 함수로 옮겨 역방향 desktop 호출을 제거했습니다.

## 현재 Rust 소비자 계약

- `Session::new`는 검증한 StartupConfig·입구 좌표·크기·0/1 지형을 소유합니다. 호스트가 완전한 기술 수량·강철/방향 마스크·객체 맵·함정·완료 조건을 구성한 뒤 실행을 시작합니다. 자산 디코딩은 session의 책임이 아닙니다.
- `queue`는 현재 제어 경계의 입력 순서를 부여합니다. 기술은 core의 안정된 개체 ID를 사용하며 `command`는 기술/ID를 동일한 명령으로 변환합니다. 포인터 request의 우선/대체 대상 결정과 RightClickGlitch는 기존 규칙을 유지합니다.
- `tick` 한 번은 논리 제어 호출 한 번입니다. Pause 중에도 제어 경계가 전진하며 게임 iteration·시계 정지는 기존 계약을 따릅니다. 생성/개체/직업/함정/판정 순서를 변경하지 않습니다.
- `due(Duration)`는 호스트가 전달한 경과 시간의 호출 수만 계산합니다. 자체적으로 tick하지 않으며 남은 위상을 유지합니다. Dos는 `2190197/156250`, Reference는 `17/1` 호출/초이고 게임의 17틱 시계와 분리합니다. 호스트는 렌더와 무관하게 반환된 모든 호출을 순서대로 처리합니다.
- 완료된 세션은 결과·논리 상태를 고정하고 새 게임 입력을 거부합니다. 동일/다음 레벨은 호스트가 새 자산·Session/View를 준비한 뒤 교체합니다. 입력/시계/선택 기억은 새 실행에서 시작합니다. 기존 lifecycle의 준비 실패 검사를 유지합니다.
- 오류는 기존 `Result<_, Box<dyn Error>>`입니다. 호출자는 오류를 보고하고 진행을 중단합니다. 모든 오류에서 세션 전체가 원자적으로 복원된다는 새로운 보장은 추가하지 않습니다. 공개 내부 필드는 네이티브 호환을 위해 유지합니다.

## G09 후속 호스트 계약

아래 항목은 구현 전 계약이며 이번 이슈에서 브라우저 실행 완료로 계산하지 않습니다.

자산 공급은 파일 이름과 바이트를 받는 별도 호스트 경계로 바꿉니다. 파서와 순수 장면 합성은 공유하고 파일 읽기·네트워크 접근은 호스트에 남깁니다. 원본 자산을 배포물에 포함하지 않으며 자체 합성 자산으로 깨끗한 환경의 검증 경로를 제공합니다. 누락·손상·지원하지 않는 레벨은 실행 교체 전에 오류로 보고해야 합니다.

WASM 경계는 입력 enum/ID·범위·수량을 확인하고 소유권이 분명한 생성/진행/상태 읽기/해제 API로 감쌉니다. 현재 Rust 구조체의 주소/필드를 JS에 직접 노출하는 방식은 사용하지 않습니다. JS 바인딩과 오류 직렬화·출력 버전은 해당 구현 이슈에서 고정합니다. 이번 rlib 컴파일만으로 링크 가능한 브라우저 모듈이나 JS ABI가 완성됐다고 표시하지 않습니다.

브라우저 프레임 시간은 세션 밖에서 경과 시간으로 변환합니다. [requestAnimationFrame 문서](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)의 가변 호출 간격과 숨겨진 탭 중단을 고려해 렌더 프레임을 논리 틱으로 사용하지 않습니다. 정상 프레임 지연의 호출 수는 버리지 않고 순서대로 처리합니다. 탭 숨김/복귀를 게임 Pause와 어떻게 연결할지는 브라우저 입력 이슈에서 입력 로그·시간 기준점 초기화 테스트와 함께 고정합니다.

화면은 현재 320×200 논리 RGB(상부320×160과 패널)를 기준으로 합니다. Canvas 확대·letterbox·포인터 좌표 변환은 호스트 책임이며 장면 그리기가 논리 상태를 바꾸면 안 됩니다. 키/포인터/패널/미니맵·우클릭/포커스 소실을 네이티브 입력 의미로 연결하고 시도별 안정 ID 입력 재생을 남깁니다.

최종 G09 검증은 같은 초기 자산·제어 경계 입력으로 네이티브와 실제 브라우저의 전체 정규화 개체/직업/객체/판정 상태·순서 있는 지형 변형·최종 바이너리 맵을 대조합니다. 렌더 간격과 경과 시간 분할을 바꾸고 성공·실패·재시작/다음 레벨·손상/누락/교체 실패를 확인합니다. 라이브러리 컴파일, 네이티브 재생, 브라우저 실행, DOS 비교를 서로 다른 증거로 기록합니다.

## 재현과 증거

```sh
source assets/local/dev-tools/env.sh
cargo test -p lemmings-session --locked --offline
cargo tree -p lemmings-session --target wasm32-unknown-unknown --edges normal --locked --offline
cargo build -p lemmings-session --lib --target wasm32-unknown-unknown --locked --offline
make check
```

추출 전 main `93578a2` 실행 파일을 별도로 보존하고 네 합성 사례와 원본 Fun01 성공/Nuke 실패를 캡처했습니다. 같은 입력을 새 실행 파일의 렌더1/7로 재생해 전체 정규화 상태·각 경계의 지형/객체 변형과 모든 초기/최종 bin·논리 RGB를 비교합니다. 입력·실행 파일·검증 스크립트·증거 목록 해시는 [매니페스트](../../assets/manifests/shared_session.json)에 기록합니다. 새 DOS 녹화나 실제 브라우저 실행은 이 증거에 포함하지 않습니다.
