# 날짜별 작업일지

해당일의 작업을 GitHub 이슈 번호로 식별할 수 있는 목록으로 기록합니다.

## 작성 규칙

- 파일명은 Asia/Seoul 작업일자 기준 `yyyymmdd.md`입니다. 예: [20261018.md](20261018.md).
- 하루 한 파일을 사용하고 같은 날의 후속 작업은 기존 파일에 추가합니다. 이 README는 작성 규칙과 색인으로 유지합니다.
- GitHub 이슈를 먼저 등록하고 번호·URL을 조회해 확인한 뒤 일지 작성과 작업을 시작합니다.
- 상단의 이슈별 목록에 이슈 링크, 작업 내용, 상태를 적습니다. 상세 기록은 `## issue-<번호>` 제목으로 연결합니다.
- 이슈별로 목표·범위·완료 기준, 수행 내용, 검증 명령·결과, 다음 행동을 목록으로 남기고 관련 계획·진행·보고 문서를 연결합니다.
- 여러 날에 걸친 이슈는 매일 실제 수행한 내용을 기록하고 이전 일지를 연결합니다. 과거 검증 결과는 수행 당시의 기록임을 표시합니다.
- 이슈 도입 전 기록은 그 사실과 이관을 추적하는 이슈를 명시하며 과거 작업 번호를 임의로 만들지 않습니다.

## 기록 형식

```md
# YYYY-MM-DD 작업일지

## 이슈별 작업 목록

- #번호 — 작업 내용 · 진행/검증/완료 (실제 이슈 URL과 상세 기록 연결)

## issue-번호

- 이슈: 번호와 GitHub URL
- 목표·범위·완료 기준:
- 수행 내용:
- 검증 명령·결과:
- 다음 행동과 관련 문서:
```
