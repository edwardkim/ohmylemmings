# 플레이 중 FPS 표시와 성능 피드백

담당 [#113](https://github.com/edwardkim/ohmylemmings/issues/113). 메인테이너는 FPS를 보며 실제 플레이 피드백을 받는 방식을 제안하고 2026-10-24 구현을 지시했다.

## 구현 계약

- Web/Native에서 기본 OFF, F3 표시 전환, F2 측정 요약 복사. Web에는 버튼과 수동 복사 대안도 제공한다. 전체화면에서도 표시한다.
- Web은 실제 rAF 콜백 진입 간격과 별도의 Canvas 갱신/s, Native는 SDL present 호출 간격을 측정한다. 물리 화면 주사율이나 논리 틱 수로 부르지 않는다.
- 최근 최대240개 간격의 FPS·p95/최대 간격, 측정 구간 전체의 50ms 초과 간격 수를 표시한다. 갱신은 최대 초당2회, 저장 공간은 고정한다.
- 로딩·숨김·일시정지·파일 선택·결과 화면은 측정을 보류하고 재개 첫 간격을 연결하지 않는다. 레벨/표시 모드 교체와 다시 켜기는 측정을 새로 시작한다.
- 피드백에는 버전·플랫폼/브라우저 또는 SDL renderer·레벨·표시 모드·창 크기·측정 요약과 체감 의견 자리만 담는다. 사용자 음원/경로를 포함하거나 자동 전송하지 않는다.
- 게임 논리/오디오/렌더 주기와 기존 성능 증거·NOT READY는 유지한다. 현재 저사양 호스트에서 중단한60초 반복을 재개하지 않는다. 이 기능의 검증을60fps 합격으로 계산하지 않는다.

## 검증 계획

1. 고정 간격/일시 중단/재설정/긴 간격/상한 버퍼의 Rust 및 실제 JS 단위 검증을 먼저 실패시킨다.
2. 실제 앱에서 F3/F2·수동 복사·전체화면·멈춤/재시작과 논리/화면/오디오 회귀를 확인한다.
3. UI 스크린샷·체크 결과·자체 검토를 보고서에 기록하고 PR/CI로 전달한다. #113의 고성능 환경 재검증은 별도 잔여다.
