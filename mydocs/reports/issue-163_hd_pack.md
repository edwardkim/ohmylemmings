# #163 HD 자산 팩 정리

이슈: https://github.com/edwardkim/ohmylemmings/issues/163 · 상위 [#137](../plans/issue-137_2d_remaster.md)

32개 원본 PNG와440개 제작 프레임을 그대로 유지하며 런타임 atlas를32개에서27개로 줄였다. 팩은133,385,948→131,699,864바이트로1,686,084바이트(약1.26%) 줄었다. 기존 v1/128MiB/32atlas/4096px 한도와 구버전 팩 호환성을 유지한다. 추가 슬롯5개를 확보했지만 메모리 여유는 약2.4MiB뿐이므로 큰 특수 배경을 모두 넣을 수 있다는 뜻은 아니다. 대규모 확장에는 테마별 로딩 등 별도 검토가 필요하다.

## 구현과 검토

`compact-v1`은 같은 cutoff의 전체 프레임 사각형을 결정론적으로 배치한다. 가시 영역 바깥2픽셀과1샘플 복사 여백을 보호하며 cutoff 이하 경계만 공유한다. 원본 PNG/출처 pin, 제작 rect, 프레임 크기·표시 크기·기준점은 그대로다. 공유된 투명 채움 RGB까지 원본과 같다는 주장은 하지 않는다. 제작 입력 수만128개로 분리하고 런타임 제한은 유지한다.

절삭 시험은 Native 축소 출력 차이 때문에 폐기했다. 전체 사각형을 유지한6atlas 시험도 Canvas 소수 축소의 샘플 위상 차이 때문에 폐기했다. 최종안은 민감한23개 소스에 `sampling_locked: true`를 지정하여 기존 `rectangles-v1` 페이지 전체와 좌표·RGBA를 유지한다. 나머지9개만 통합한다. 원본 PNG로 재빌드한 결과가 시험 후보와 SHA-256까지 같음을 확인했다. 이 경험 때문에 새 자산을 추가할 때도 실제 Native/Canvas 비교가 필요하다.

self-review: 원본 시뮬레이션·Rust 렌더러·입력·사운드·틱 코드는 변경하지 않았다. CRC, cutoff 그룹, 중복 영역, 보호 경계, 페이지/용량/크기 제한과 기존 캐시의 소스 해시 검증을 유지했다. 배치 고정의 bool 검증·기존 페이지 바이트 동일성·제한 초과를 회귀 테스트로 추가했다.
