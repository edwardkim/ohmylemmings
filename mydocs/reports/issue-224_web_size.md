# Web 배포 용량 증가 조사

담당 [#224](https://github.com/edwardkim/ohmylemmings/issues/224). 2026-10-25 공개 릴리즈의 실제 ZIP을 비교했다. 제품·패키징 변경 없이 조사만 수행했다. 아래 MB는10진수1,000,000바이트다.

## 결론

v0.3.1→v0.3.2 전체 Web ZIP은192,429,585→218,032,420바이트(+25,602,835, +13.305%)다. 증가분94.529%가 `audio-source.tar.gz`의 ZIP 내부 압축 크기 증가다. WASM 자체 증가가 주원인이 아니다.

| 분류 | v0.3.1 ZIP 내 압축 바이트 | v0.3.2 ZIP 내 압축 바이트 | 증가 |
|---|---:|---:|---:|
| 대응 소스 tar.gz | 96,265,735 | 120,467,730 | 24,201,995 |
| HD 런타임53페이지 | 95,410,064 | 96,803,678 | 1,393,614 |
| WASM | 257,562 | 261,817 | 4,255 |
| 원본 데이터28파일 | 376,139 | 376,139 | 0 |
| 기타 | 101,849 | 104,710 | 2,861 |

ZIP 헤더/디렉터리 오버헤드는 위 분류 합계에 포함되지 않는다. 실제 `.wasm`의 비압축 크기는1,053,544→1,060,121바이트(+6,577, 약0.62%)다. 소스 tar.gz 자체는96,302,747→120,495,680바이트다. 이름과 달리 오디오 코드만 들어 있지 않다.

## 소스 묶음이 커진 이유

`tools/web_build.py::source_bundle`은 추적 중인 apps/crates/tools뿐 아니라 assets·mydocs 등 허용된 전체 경로를 묶는다. 현재 사용 중인지와 무관하게 과거 HD 원본 PNG·디자인 후보·프리뷰도 포함한다. Git 이력 전체를 넣는 것은 아니며 현재 tree에 남아 있는 파일을 넣는다.

소스 내부 `assets/remaster` 비압축 합계는93,426,551→117,688,283바이트(+24,261,732)다. 주요 신규 파일은 #215의5재질 PNG 약14.64MB와 입출구/시설5PNG 약9.15MB다. 기존 v1 이미지도 보존되어 있다. 이미 압축된 PNG는 tar.gz/ZIP 재압축 효과가 작다. 따라서 개선된 런타임 페이지의 증가보다 새 제작 원본의 누적이 훨씬 크다.

현재 패키지는 HD 실행 데이터와 그 제작용 소스 자산을 함께 전달한다. 개념적으로 같은 미술 콘텐츠가 두 형태로 포함되지만 서로 다른 바이트/용도이며 단순 중복 파일이라고 단정하지 않는다.

장기 추이(공개 ZIP 바이트): v0.1.0 4,919,566 / v0.2.0 191,738,519 / v0.3.0 192,081,420 / v0.3.1 192,429,585 / v0.3.2 218,032,420. 큰 변화는 HD 리마스터 도입 시점이다. 이번 상세 파일별 대조는0.3.1/0.3.2에 한정한다.

## 첫 로딩과 전체 패키지는 다르다

각 공개 ZIP에서 JS/WASM·원본 데이터·HD-WEB.json을 추출하고 Node에서 해당 실제 WASM을 초기화해 Fun01 `hd_download_plan(false)`를 얻었다. 매니페스트의 같은 선택 규칙으로 페이지 크기를 합산했다.

| HD 항목 | v0.3.1 | v0.3.2 |
|---|---:|---:|
| Fun01 필수 페이지 수 | 8 | 9 |
| 필수 압축 다운로드 바이트 | 19,751,567 | 19,668,307 |
| 필수 페이지 해제 바이트 | 46,181,352 | 44,892,052 |
| 전체 압축 HD 바이트 | 95,537,433 | 96,920,745 |

첫 레벨 HD 필수 용량은83,260바이트 줄었다. 여기에는 엔진·JS/CSS·원본 데이터·HTTP 헤더·백그라운드 프리페치가 포함되지 않는다. 새 브라우저 네트워크 실측이나 전체 메모리 사용량도 아니다.

`app.js`는 WASM·원본 데이터·현재 레벨 HD를 읽고 `progressive-hd.js`가 다음 레벨을 프리페치한다. `audio-source.tar.gz`는 `audio-license.html`의 다운로드 링크이며 JS 자동 fetch 경로가 없다. 즉120.5MB의 소스는 사이트/ZIP 저장 용량에는 포함되지만 일반 게임 시작 시 자동 다운로드하지 않는다.

## 개선 우선순위

1. 배포 전체 용량: 대응 소스 전달을 실행 ZIP과 분리하거나, 재빌드에 필요한 자료와 과거 디자인/프리뷰·보고 자료를 구분하는 방안을 검토한다. LGPL/MPL 고지·대응 소스 접근·수정/재링크 가능성과 정확한 버전 연결을 보존해야 하며 소스를 무조건 삭제하는 방안은 아니다. 현재 소스 파일을 ZIP 밖으로 옮기기만 할 경우 실행 ZIP 약120.47MB 감소가 산술적 상한이며 전체 호스팅 용량 자체가 줄어드는 것은 아니다.
2. 첫 실행 속도: 소스 묶음 분리는 영향이 거의 없다. 약19.67MB인 Fun01 HD의 이미지/전송 포맷·페이지 구성 최적화가 우선이다.
3. WASM 코드 최적화: 비압축1.06MB이고 이번 증가가6.6KB이므로 이번 용량 문제의 우선순위는 낮다.

## 증거와 검증

- v0.3.1 ZIP SHA-256: `b6658a9a56f8ff47b9df2cbdcbb62a193b27f1390e0ed775050823bfc90c9ea2`
- v0.3.2 ZIP SHA-256: `842d06edc3c1f3eb24d904acb96cc15bc55147cd13c3358e9e2097859a41af96`
- 실제 공개 ZIP 크기·hash는 기존 릴리즈 검증 기록과 일치한다. ZIP 중앙 디렉터리의 압축/비압축 크기, 소스 tar 멤버별 크기, 각 실제 WASM의 로딩 계획을 사용했다.
- 개인 증거/스크립트: 루트 worktree의 ignored `assets/local/issue-224-size/` (`analysis.json`, `initial.json`, `analyze.py`, `initial.mjs`). 원본 포함 ZIP/추출 데이터는 Git에 추가하지 않는다.
- 문서 self-review·상대 링크·git diff --check만 수행한다. 코드 변경·패키지 재배포·새 성능 인수는 없다.
